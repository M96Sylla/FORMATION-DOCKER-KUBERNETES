Étape 01 · Ouverture

Administrer Kubernetes

Trois jours, une machine virtuelle par personne, un cluster Minikube monté de vos mains dès le premier après-midi. À la fin, vous saurez installer un cluster, y faire tourner des applications, les exposer, les sécuriser et diagnostiquer ce qui ne marche pas.

Le fil de la formation est celui du métier : on part de l'architecture, on construit, on déploie, on expose, on protège, on dépanne. Chaque module se termine par un atelier sur votre propre cluster. Rien n'est simulé, rien n'est préinstallé.

Deux règles pour ces trois jours : on coupe quand quelque chose n'est pas clair, et on casse volontairement des choses pour comprendre comment elles se réparent.

Ce qui vous attend
17 modules, 16 ateliers, un cluster monté depuis zéro sur votre VM avec Minikube. Le questionnaire final du module 17 reprend l'ensemble du parcours.

Étape 03 · L'écosystème

La Linux Foundation

La Linux Foundation est une fondation à but non lucratif créée en 2000. Elle héberge le noyau Linux et environ un millier de projets open source, dont la CNCF (Cloud Native Computing Foundation), qui abrite Kubernetes depuis 2015.

Ce que cela change concrètement pour vous : personne ne possède Kubernetes. La spécification, les API et le programme de conformité sont publics. Un cluster certifié conforme se comporte de la même manière chez un hébergeur, chez un fournisseur cloud ou sur votre VM.

La fondation publie aussi un catalogue de formations et des certifications indépendantes des éditeurs. Ce cours suit la trame du parcours d'administration Kubernetes, avec des travaux pratiques adaptés au format présentiel et à une machine unique.

Pourquoi ça compte
Le test de conformité CNCF (Sonobuoy, vu au module 16) est ce qui garantit la portabilité. Une distribution qui échoue au test n'a pas le droit d'utiliser le nom Kubernetes. C'est aussi ce qui rend l'apprentissage sur Minikube transposable : les mêmes API, les mêmes objets, les mêmes commandes qu'en production.

Étape 05 · Environnement

Une VM, un Cluster : Minikube

Chacun dispose d'une machine virtuelle Ubuntu unique. Nous y installerons Minikube, qui fabrique un cluster Kubernetes complet à l'intérieur d'un conteneur Docker tournant sur cette VM. Pas de virtualisation imbriquée, pas de second serveur, pas de compte cloud.

Il faut être clair sur ce que Minikube est et n'est pas. Ce n'est pas une version allégée de Kubernetes : à l'intérieur du nœud tourne un vrai plan de contrôle, installé par kubeadm, avec les mêmes composants, les mêmes certificats et les mêmes fichiers qu'en production. Nous irons les regarder au module 3.

Ce qui manque est ailleurs : la haute disponibilité, la répartition sur des machines physiques distinctes, et le comportement d'un réseau d'entreprise. Chaque fois qu'un écart avec la production compte, un encadré vert le signale.

Le minimum matériel

2 vCPU, 4 Go de RAM et 25 Go de disque libres sur la VM. Le cluster se contente de 2 Go, le reste sert aux images et aux ateliers du jour 2.

Les conventions

Le préfixe $ désigne une commande à saisir sur la VM. Les fichiers YAML sont créés dans ~/k8s. Toutes les commandes sont fournies, il n'y a rien à deviner. Et si le mot saucisse revient dans tous les ateliers, ce n'est pas une erreur de frappe : c'est la signature de ce support.

Étape 06 · QCM

Vérifiez vos Acquis

QUESTION 01
Kubernetes appartient à la CNCF, qui décide seule des évolutions du projet.
Gouvernance ouverte

La CNCF héberge le projet et finance l'infrastructure. Les décisions techniques appartiennent aux SIG et au comité de pilotage, ouverts à tous les contributeurs.

QUESTION 02
L'examen CKA se déroule dans un terminal, sur de vrais clusters.
Examen pratique

Aucune question à choix multiple. On vous donne des tâches et un accès aux clusters, la correction porte sur le résultat obtenu.

QUESTION 03
Minikube est une réimplémentation simplifiée de Kubernetes.
Le vrai Kubernetes

Minikube installe les composants officiels dans un nœud unique, via kubeadm. Les API, les objets et les commandes sont rigoureusement les mêmes qu'en production.

QUESTION 04
Un cluster à un seul nœud ne permet pas d'observer la haute disponibilité.
La limite assumée

Tout le reste s'étudie normalement. Pour la répartition entre nœuds, Minikube sait ajouter des nœuds supplémentaires sur la même machine, ce que nous ferons au module 3.

Étape 07 · Atelier

Atelier 1 : Préparer la VM

Atelier 01 · 25 minutes

Inventorier la machine et installer le moteur de conteneurs

Minikube s'appuiera sur Docker comme pilote. On vérifie d'abord que la VM est apte, puis on installe le moteur et on valide qu'il fonctionne sans sudo.

1. Inventaire
Version d'Ubuntu et architecture $ lsb_release -a ; uname -m Processeurs (2 minimum) et memoire (4 Go recommandes) $ nproc ; free -h Espace libre sur la racine (25 Go recommandes) $ df -h / Adresse IP de la VM : notez-la, elle servira aux modules 14 et 15 $ ip -4 addr show scope global | grep inet Acces reseau vers les depots $ curl -sI https://registry.k8s.io | head -1
2. Installer Docker Engine
$ sudo apt-get update $ sudo apt-get install -y ca-certificates curl gnupg $ sudo install -m 0755 -d /etc/apt/keyrings $ curl -fsSL https://download.docker.com/linux/ubuntu/gpg \ | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg $ echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \ https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" \ | sudo tee /etc/apt/sources.list.d/docker.list $ sudo apt-get update $ sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin
3. Utiliser Docker sans sudo, et valider
Minikube refuse de demarrer si Docker exige sudo $ sudo usermod -aG docker $USER Ouvre un shell avec le nouveau groupe, sans se deconnecter $ newgrp docker $ docker run --rm hello-world $ docker info | grep -E 'Server Version|Cgroup Driver|Storage Driver' $ mkdir -p ~/k8s && cd ~/k8s
Validation

La VM est prête si nproc renvoie au moins 2, s'il reste au moins 20 Go sur /, et si docker run hello-world aboutit sans sudo. Si la commande docker réclame encore les droits, fermez complètement le terminal et rouvrez-en un : l'appartenance au groupe n'est prise en compte qu'à l'ouverture d'une session.
