Étape 01 · L'outil

Installer le Cluster

Minikube est un outil de la communauté Kubernetes qui fabrique un cluster complet sur une seule machine. Il prépare un environnement isolé (ici un conteneur Docker), y installe les binaires, exécute kubeadm à l'intérieur, télécharge les images du plan de contrôle et écrit votre fichier de connexion.

Ce qu'il faut avoir en tête : Minikube n'est pas un Kubernetes différent. C'est un installateur et un gestionnaire de cycle de vie. Une fois démarré, ce qui tourne dans le nœud est exactement ce qui tournerait sur un serveur de production, aux mêmes emplacements, avec les mêmes commandes.

Ce qu'il fait en plus, et qui nous servira beaucoup : il gère les modules complémentaires, sait ajouter des nœuds, ouvre un accès aux services et sait tout détruire proprement pour recommencer.

Le filet de sécurité
minikube delete puis minikube start reconstruit un cluster neuf en quelques minutes. Vous pouvez donc casser sans crainte pendant trois jours, ce qui est précisément l'intérêt de cet environnement.
Étape 02 · Les choix

Pilotes, Profils & Options

Le pilote détermine où vit le nœud. C'est la décision structurante au démarrage, et elle ne se change pas ensuite sans recréer le cluster.

docker

Le nœud est un conteneur sur la VM. Démarrage rapide, aucune virtualisation imbriquée requise. Notre choix.

--driver=docker

kvm2, virtualbox

Le nœud est une machine virtuelle complète. Isolation plus forte, mais impose que la VM sache virtualiser à son tour.

indisponible ici

none

Kubernetes s'installe directement sur la machine hôte, sans isolation. Rapide, mais impossible à nettoyer proprement.

à éviter
Les options qui comptent pour ces trois jours $ minikube start \ --driver=docker \ --cpus=2 --memory=3g \ # ressources allouees au noeud --cni=calico # plugin reseau, obligatoire pour le module 13 Autres options utiles --kubernetes-version=v1.34.0 # figer une version precise --nodes=2 # plusieurs noeuds sur la meme machine -p demo # un profil, donc un cluster independant
Le choix du plugin réseau
Par défaut, Minikube installe un plugin minimal qui ignore silencieusement les politiques réseau. Vos règles du module 13 sembleraient acceptées sans jamais rien bloquer. Nous imposons donc Calico dès le démarrage, ce qui évite de reconstruire le cluster au jour 3.
Étape 03 · Sous le capot

Ce qu'il y a Dans le Nœud

Le nœud Minikube est une machine Linux comme une autre, accessible par minikube ssh. À l'intérieur, kubeadm a déposé la même arborescence que sur n'importe quel cluster.

/etc/kubernetes/ ├── manifests/ # pods statiques, surveilles par le kubelet │ ├── etcd.yaml │ ├── kube-apiserver.yaml │ ├── kube-controller-manager.yaml │ └── kube-scheduler.yaml ├── pki/ # l'autorite de certification et ses certificats │ ├── ca.crt ca.key │ ├── apiserver.crt apiserver.key │ └── etcd/ ├── admin.conf # l'acces administrateur complet └── kubelet.conf # identite du kubelet local

Le répertoire manifests est surveillé en permanence par le kubelet : modifier un fichier y provoque le redémarrage du composant correspondant, sans passer par l'API server. C'est ainsi que l'on change un paramètre de l'API server, et c'est aussi la porte de secours quand plus rien ne répond.

Le répertoire pki contient l'autorité de certification. Sa clé privée permet de signer n'importe quelle identité du cluster, y compris administrateur. Elle se sauvegarde et se protège comme un secret de premier niveau.

Étape 04 · L'accès

kubectl & le Fichier kubeconfig

kubectl est un client HTTP. Il n'a aucun pouvoir propre : il lit un fichier de configuration, y trouve une adresse d'API server et une identité, puis envoie des requêtes REST. Tout ce que vous pouvez faire dépend des droits attachés à cette identité.

Ce fichier, par défaut ~/.kube/config, articule trois listes et un pointeur. Minikube y ajoute son contexte et le sélectionne automatiquement au démarrage.

clusters: # une adresse d'API server + le certificat de l'autorite - name: minikube cluster: { server: https://192.168.49.2:8443, certificate-authority: ~/.minikube/ca.crt } users: # une identite : certificat client, jeton ou plugin - name: minikube user: { client-certificate: ..., client-key: ... } contexts: # un couple (cluster, utilisateur) + un namespace par defaut - name: minikube context: { cluster: minikube, user: minikube, namespace: default } current-context: minikube
Sur le terrain
L'identité créée par Minikube, comme l'admin.conf de kubeadm, appartient au groupe system:masters, qui contourne entièrement RBAC. En production, ce fichier ne se distribue pas. Au module 12, vous créerez des accès nominatifs à droits limités, seule pratique acceptable à plusieurs.
Étape 05 · Exploitation

Piloter le Cluster au Quotidien

Cycle de vie $ minikube status # etat des composants $ minikube stop # arret propre, l'etat est conserve $ minikube start # redemarrage avec les memes options $ minikube delete # destruction totale, sans confirmation Acces $ minikube ssh # shell dans le noeud $ minikube ip # adresse du noeud, vue de la VM $ minikube service NOM # ouvre un acces vers un service (module 14) $ minikube tunnel # simule un repartiteur de charge (module 14) Modules complementaires $ minikube addons list $ minikube addons enable metrics-server $ minikube addons enable ingress # module 15

Les modules complémentaires sont de simples manifestes appliqués dans le cluster. Rien de magique : minikube addons enable metrics-server crée exactement le même Deployment que vous auriez appliqué à la main sur un cluster de production. Vous pourrez d'ailleurs les lire avec kubectl get all -n kube-system.

Deux commandes à ne pas confondre
minikube stop éteint le nœud et conserve tout : vos objets seront là demain matin. minikube delete supprime le cluster et son contenu, sans demander confirmation. Le premier termine la journée, le second sert à repartir de zéro.
Étape 06 · QCM

Vérifiez vos Acquis

QUESTION 01
Minikube installe une version allégée du plan de contrôle.
Les vrais composants

À l'intérieur du nœud, kubeadm installe l'API server, etcd, le scheduler et le controller-manager officiels, sous forme de pods statiques. Seule l'échelle change.

QUESTION 02
Le choix du plugin réseau se fait au démarrage et conditionne les politiques réseau.
Décision structurante

Le plugin par défaut accepte les NetworkPolicy sans jamais les appliquer. Calico ou Cilium sont nécessaires pour qu'elles aient un effet réel.

QUESTION 03
Modifier un fichier de /etc/kubernetes/manifests redémarre le composant concerné.
Pods statiques

Le kubelet surveille ce répertoire et applique tout changement immédiatement, sans l'API server. C'est le seul moyen de reconfigurer l'API server, et la porte de secours quand il ne répond plus.

QUESTION 04
minikube stop détruit les objets créés dans le cluster.
Il conserve tout

L'arrêt éteint le nœud sans toucher à etcd. C'est minikube delete qui supprime le cluster et son contenu, sans demander confirmation.

Étape 07 · Atelier

Atelier 3 : Démarrer le Cluster

Atelier 03 · Partie 1 · 25 minutes

Installer kubectl et Minikube, puis lancer le nœud

1. Les deux binaires
kubectl, version stable courante $ cd ~ && curl -LO "https://dl.k8s.io/release/$(curl -Ls https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl" $ sudo install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl $ kubectl version --client minikube $ curl -LO https://storage.googleapis.com/minikube/releases/latest/minikube-linux-amd64 $ sudo install minikube-linux-amd64 /usr/local/bin/minikube $ minikube version
2. Démarrer (comptez 3 à 6 minutes la première fois)
$ minikube start --driver=docker --cpus=2 --memory=3g --cni=calico Si la VM est juste en memoire, descendez a --memory=2200mb $ minikube status Le noeud est un conteneur sur votre VM : verifiez-le $ docker ps --filter name=minikube Attendu : Ready. Calico peut prendre une minute de plus. $ kubectl get nodes -o wide $ kubectl get pods -A
3. Confort de travail
$ echo 'source <(kubectl completion bash)' >> ~/.bashrc $ echo 'alias k=kubectl; complete -o default -F __start_kubectl k' >> ~/.bashrc $ source ~/.bashrc $ kubectl config get-contexts $ kubectl cluster-info
En cas d'échec

Lisez le message, Minikube nomme précisément le prérequis manquant. Les deux causes fréquentes : Docker exige encore sudo (reprenez l'atelier 1), ou la mémoire demandée dépasse celle de la VM. minikube delete puis un nouveau start repartent proprement.

Étape 08 · Atelier

Atelier 3 : Ouvrir le Capot

Atelier 03 · Partie 2 · 25 minutes

Retrouver dans le nœud tous les composants du module 2

1. À l'intérieur du nœud
$ minikube ssh Les quatre pods statiques du plan de controle $ ls -l /etc/kubernetes/manifests/ Les arguments reels de l'API server $ sudo grep -E 'advertise-address|service-cluster-ip-range|authorization-mode' \ /etc/kubernetes/manifests/kube-apiserver.yaml L'autorite de certification $ sudo ls /etc/kubernetes/pki/ Le kubelet, seul composant non conteneurise $ systemctl status kubelet --no-pager | head -5 Le runtime et la configuration reseau $ ls /etc/cni/net.d/ $ exit
2. Les mêmes composants, vus par l'API
$ kubectl get pods -n kube-system -o wide Un pod statique porte le nom du noeud en suffixe $ kubectl get pod -n kube-system -l component=kube-apiserver Les journaux du plan de controle, comme n'importe quel pod $ kubectl logs -n kube-system -l component=kube-scheduler --tail=10
3. Modules complémentaires et premier pod
$ minikube addons list | head -20 $ minikube addons enable metrics-server $ kubectl get deploy -n kube-system metrics-server $ kubectl run saucisse-1 --image=nginx:1.27 --port=80 $ kubectl get pod saucisse-1 -o wide $ kubectl describe pod saucisse-1 | tail -12 Depuis le noeud, sur l'IP du pod affichee ci-dessus $ minikube ssh -- curl -s -o /dev/null -w "%{http_code}\n" http://<IP-DU-POD>
4. Bonus : un deuxième nœud
Uniquement si la VM dispose de memoire libre $ minikube node add $ kubectl get nodes $ kubectl get pods -A -o wide | grep -c minikube-m02
Validation

Vous devez pouvoir citer, fichier à l'appui, où se trouvent les manifestes du plan de contrôle, où se trouve l'autorité de certification, et quel plugin réseau est actif. Le pod saucisse-1 doit répondre 200. Conservez-le, il sert au module 4.

Étape 09 · Conclusion

Récapitulatif du Module 3

  • Minikube installe un vrai cluster via kubeadm dans un nœud unique, et en gère le cycle de vie.
  • Options structurantes : pilote docker, ressources allouées, et surtout --cni=calico pour que les politiques réseau du module 13 soient réellement appliquées.
  • Dans le nœud : /etc/kubernetes/manifests pour reconfigurer, pki pour l'autorité de certification, kubelet en service systemd.
  • kubectl : un client REST dont tous les pouvoirs viennent du kubeconfig, structuré en clusters, users et contexts.
  • Réversible : stop conserve, delete détruit. On peut repartir de zéro en quelques minutes.
